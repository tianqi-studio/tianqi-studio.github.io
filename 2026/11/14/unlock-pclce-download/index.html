主要内容

我基于pcl社区版制作了这个解除下载限制的版本。

起因

我11月20号一觉醒来天塌了，发现pcl因为熊孩子在服务器充钱，神人家长连pcl一起举报了目前暂无定论的原因被举报，关闭了下载功能。

#3673 fix(install): 中国大陆地区禁用 Minecraft 安装功能

原版的地区限制是怎么运作的？
限制逻辑是一条读信号 → 分类 → 判定拦截的链路，分两层：

第 1 层：RegionPolicy.cs（信号与分类）​
  1. ReadWindowsSignals() 读取 Windows 的两项地区信号：
  • GeoName：系统”国家或地区”设置（经 GetUserDefaultGeoName / 旧 API GetGeoInfoW 拿 ISO 代码 CN 或 156）
  • TimeZone：本地时区（TimeZoneInfo.Local.Id，如 China Standard Time）
  1. Evaluate(signals) 把信号归类为三种 RegionClassification：
  • Mainland（中国大陆）：时区是中国 + 设备地区是中国
  • Unknown：信号不足、无法确认
  • Other：其它
  1. RegionAssessment.IsRestricted：Classification == Mainland 即视为受限（旧版是 Mainland or Unknown）
第 2 层：RestrictedFeaturePolicy.cs（拦截入口）​

所有”需要补文件”的功能——下载客户端、安装/补全/重置实例、整合包（本地/在线/自动）、Mod 加载器安装、启动缺文件检查——全部汇聚到 Check() / ThrowIfRestricted()：

  • 受限时 Check 返回 false 并弹出 Region.Feature.Restricted 提示；ThrowIfRestricted() 直接抛 CancelledException
  • PCL.Launcher.Core侧是通过 WpfRestrictedFeatures 桥接回这里，所以只改这一处就能覆盖全部入口（”9 个 WPF 入口”都收敛于此）

经过

ai是怎么解除的（改了 2 个文件）

核心思路：在”返回值”层面收敛，而不是去伪造信号。这一点很重要——注释里专门强调，不能用”清空信号/伪装成别国”的方式绕，因为旧版会把”信号不足”判成 Unknown 并继续拦截；只有让 Evaluate 永远不返回 Mainland/Unknown，才能对所有信号组合成立。

1. RegionPolicy.cs 加总开关 + 收敛返回值

同时给分类判定的属性也加了开关与门：

用 static readonly而非 const，是避免编译器把”停用后的原始判定”折叠成不可达代码的 CS0162 警告。

2. RestrictedFeaturePolicy.cs加统一门闩

RestrictionEnabled == false时，Check()直接 return true，ThrowIfRestricted() 也走 Check(..., false) 直接放行、不再抛异常。因为所有入口都过这里，只改这两个文件就解除了全部下载/安装限制，无需逐个改 9 个入口。

结果

于是ai就这样改好了，但有两个问题：

  1. 联机功能无法使用。
  2. 编译出来的体积大（约80多mb）。

对此我也有解决办法：

  1. 使用其它的联机软件，市面上挺多的，我推荐樱花frp、ChamlFrp等（不是广告）
  2. 其实80多mb对电脑来说连一根毛都算不上，如果你没有这80多mb的空间我也不推荐你玩mc
