WinUI 3应用收纳器

发表于2026-11-21|更新于2026-11-21|应用开发
|总字数:2650|阅读时长:11 分钟|浏览量:

含大肥鱼生成内容

我写这个项目的起点很朴素：要打开某个软件，在桌面里找起来太烦。

Windows自带的东西其实也有，虽然Win+S搜索能用，但一遇到像我一样超多的应用就吃力了。

因此我让大肥鱼写了个软件：应用收纳器

能做什么

  • 扫描开始菜单里的快捷方式和 shell:AppsFolder 里的商店应用，自动去重，按名称粗分类
  • 分类能自己建，一个应用也可以同时属于多个分类
  • 搜索框边打边筛，按回车直接启动第一个结果
  • 全局快捷键默认 Ctrl+R，设置里能换成 Alt+R 或 Ctrl+Space
  • 托盘轻量常驻，启动后不主动弹窗；右键托盘有设置和退出
  • 三种主题：暗色、浅色、跟随系统
  • 单实例，重复启动只会把已有那个唤出来
  • 数据是一个JSON，存在 %LOCALAPPDATA%\LiquidAppManager\appdata.json

按下快捷键后窗口从屏幕底部弹出，点外面就收起。

代码怎么分层

四个目录，职责基本不重叠：

目录 职责 典型文件
根目录 应用生命周期、主窗口 App.xaml.cs、MainWindow.xaml.cs
Services 扫描、图标、数据、主题、托盘、热键 AppScanService.cs、IconService.cs
Native Win32 / DWM / 托盘结构的 P/Invoke NativeMethods.cs、NativeMessageWindow.cs
Views 设置页和应用管理页 SettingsView、ManageAppsView

依赖是手工传的。App.OnLaunched 里 new 出 repository 和四个 service，再一起塞进 MainWindow 的构造函数。没上 DI 容器，整个程序只有一个窗口，为这点依赖引一个容器不划算。

主窗口不负责自己的生命周期。它被创建完就 Hide()，什么时候显示由托盘和热键决定。真正的退出走 App.ExitApplication()，它依次拆托盘、拆热键、存盘，最后才把 _allowClose 置位允许窗口关闭。这个顺序如果反过来，会出现托盘图标残留，或者数据还没落地进程就没了。

然后呢

扫描为什么必须单开一条STA线程

读快捷方式用的是 WScript.Shell，遍历商店应用用的是 Shell.Application。这两个都是 STA 的 COM 组件，在 WinUI 主线程上初始化它们，会因为公寓模型冲突偶发 0x8001010E（调用线程必须是 STA）。

商店应用的识别不复杂，但有个容易踩的坑：AppsFolder 里只有 Path 带感叹号的才是可见应用，格式是 包族名!应用ID，比如 Microsoft.WindowsCalculator_8wekyb3d8bbwe!App。不带感叹号的是文件夹或系统项，直接跳过。

拿到 AUMID 还要找图标。AppxManifest.xml 里的 Square44x44Logo 只是相对路径，实际目录里躺着 targetsize-16 到 targetsize-256 十几个变体，还有 altform-unplated、contrast-black 这些特殊版本。选错的话，暗色任务栏上会出现一个白底方块。这里的做法是按文件名打分，targetsize-256 且不带 unplated 的排最前，依次往下，altform-unplated 垫底。

图标缓存为什么会失效

第一版缓存很简单：把「启动目标 + 图标来源」拼成字符串，算 SHA256，取前 12 字节当文件名，存成 PNG，命中就直接用。

这套东西跑了半个月没出事，直到我把某个软件的图标换了，界面上还是旧的。原因很清楚：缓存键里只有路径，没有文件内容。路径没变，键就没变，永远命中第一次生成的那张图。大肥鱼！

修法是往键里加源文件的最后写入时间：

键变了，新图会重新生成。但旧 PNG 不会自己消失，所以提取成功后顺手删掉这个应用的上一个缓存文件。删除前会判断目标确实位于本应用的 icons 目录里，免得误删系统图标。

这条路不是所有文件都通。少数开始菜单项落在 ACL 受限的目录里（比如安装程序写进 ProgramData 的工具组），StorageFile.GetFileFromPathAsync 会直接抛 UnauthorizedAccessException。现在的处理是记一条 Info 后跳过，界面显示占位图标，不把它当成错误刷屏。

弹出动画：为什么不用 Storyboard

WinUI 的 Storyboard 动的是控件属性，动不了窗口在屏幕上的位置。而面板要从屏幕下沿滑上来，动的是窗口本身。

所以这里没有 XAML 动画，就是一个 DispatcherQueueTimer，15 毫秒一帧，自己算 Y 坐标，然后 SetWindowPos：

320 毫秒展开，230 毫秒收起。这两个数是反复试出来的，再快有跳帧感，再慢就觉得拖沓。

窗口位置按光标所在显示器的工作区算，不是主屏。多屏且缩放不一致时这条很关键：1080p@100% 和 4K@150% 拼在一起，用固定像素算出来的坐标会跑到屏幕外面。所以定位前先 MonitorFromPoint 拿显示器，再 GetDpiForMonitor 拿缩放比，最后换算成物理像素。

窗口外观：两套圆角，一条去不掉的白边

Win11 的圆角是 DWM 给的，DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE) 设成 DWMWCP_ROUND 就行。Win10 没有这套，只能自己 CreateRoundRectRgn 加 SetWindowRgn 裁出来。

两套都实现之后发现一个细节：Win11 上如果同时用 DWM 圆角和 SetWindowRgn，会出现两种弧度的圆角叠在一起，Mica 材质的边缘从缝里透出来。所以现在按系统版本二选一，不做叠加。

有一条白边我没能去掉。

Win11 22H2 之后，DWM 会在窗口四周画一圈 1px 的边框。文档里有个 DWMWA_VISIBLE_FRAME_BORDER_THICKNESS，看着像是能设成 0，实际调用返回 E_INVALIDARG（0x80070057），这个属性只读。把 DWMWA_BORDER_COLOR 设成 DWMWA_COLOR_NONE 能让它变透明，但 1px 的空间还在，诊断日志里至今能看到 dwmBorder=1px。

想彻底消掉得改窗口样式、自己画边框，代价和收益不成比例，就先留着。

（这个大肥鱼改了好几次都改不好(╯▔皿▔)╯）

问题呢

裸 R 键会吞掉整个系统的 R

第一版的热键预设里有个「R」，注册时不带任何修饰键。RegisterHotKey 成功之后，所有程序都收不到 R 键了，在记事本里打不出字母 r。这个预设已经删掉，老数据加载时会自动换回 Ctrl+R。枚举值还留着，因为旧 JSON 里存的是字符串 "BareR"，直接删会让反序列化失败，进而触发数据重建。

NIF_SHOWTIP 不是设了就生效

托盘图标的悬停提示想跟着快捷键变，得先 Shell_NotifyIcon(NIM_SETVERSION) 把协议版本设成 4。之前只加了 NIF_SHOWTIP 标志，提示一直停在创建时那句话，换了快捷键也不更新。

窗口的 Closing 被自己拦住了

主窗口默认不关闭、只隐藏，所以在 AppWindow.Closing 里写了 args.Cancel = true。结果托盘菜单点「退出」时窗口关不掉，程序卡在那里。现在的做法是加一个 _allowClose 开关，ExitApplication() 里先置位再 Close()。

单实例：Mutex 加一个命名事件

互斥体判断是不是第一个实例。不是的话，往命名事件 Set 一下，第一个实例收到后把面板显示出来，第二个自己退出。中间有个时间窗：第一个实例刚拿到互斥体，事件还没建好。所以第二个实例会重试 20 次，每次间隔 50 毫秒。

数据格式改过一次

从 v1 的「一个应用一个分类」改成 v2 的「一个应用多个分类」。旧数据只有 categoryId，加载时如果 categoryIds 是空的，就把 categoryId 挪进去。主题枚举也改过名，旧的 LiquidGlass 映射成暗色、Native 映射成跟随系统，靠一个自定义 JsonConverter 兜住，避免老用户升级后启动失败。

90 MB 是怎么来的

WinUI 3 的默认模板会引 Microsoft.WindowsAppSDK 元包。这个包连带拉进 Windows ML（ONNX Runtime 加 DirectML）、AI 和 Widgets，加起来 45 MB 左右。这个项目一行都没用到。

做法是改引三个子包（WinUI、Runtime、DWrite），再用 MicrosoftWindowsAppSDKFilesExcluded 在 SDK 复制文件之前把 onnxruntime*.dll、DirectML.dll、Microsoft.Windows.AI.*、Microsoft.Windows.Widgets.*、NpuDetect 全部排除。

其它几刀：SatelliteResourceLanguages 只留 zh-CN 和 en；Release 不生成 PDB；构建后跑一遍 PowerShell，删掉多余的语言目录（每次 84 个）。

项目 优化前 现在
精简版发布目录 约 135 MB 约 90 MB
精简版压缩包 — 29.7 MB
自包含版压缩包 — 61.3 MB

顺便记一个 dotnet publish 的坑：未打包的 WinUI 3 应用，publish 只复制 Windows App SDK 的 PRI，不会复制应用自己的 AppManager.pri 和 .xbf。少了它们，发布版启动会在 XAML 解析阶段直接崩。得在 csproj 里加一个 AfterTargets="Publish" 的 Target 手动补复制。

最后

改好的1.0.1已经发在 GitHub 上，MIT 协议。两个包：精简版需要装 .NET 8 Desktop Runtime，自包含版解压即用。

没做完的部分也列一下，免得看着太完整。启动次数和最后启动时间一直在记录，但排序还没用上，现在依然按名称排。没有自动化测试，验证靠 APPMANAGER_TEST_MODE 环境变量跳过热键注册，然后手工点一遍。面板只支持贴底，不能改成居中或者贴左上。

数据全在本机，一个 JSON 加一个图标目录，删掉就等于恢复出厂。这一点我很确定，因为经常删它来测首次启动。

仓库： tianqi-studio/AppManager，遇到问题issue带上 app.log 。
